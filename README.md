# Ремонт · учёт заявок сервисного центра

Учебное настольное приложение на **Python + PyQt5 + SQLite**.
Окна и формы настоящие: это не консольная программа и не макет.

## Запуск из корня проекта

Нужен Python 3.11 или новее. Проверено на Python 3.14 и PyQt5 5.15.11 в Linux.

### Linux / macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m repair_service --demo
```

Если окружение создано через `uv`, зависимости можно установить командой
`uv pip install --python .venv/bin/python -r requirements.txt`.

### Windows, PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m repair_service --demo
```

Все команды выполняются из папки, где находятся `requirements.txt` и `run_app.py`.
Вместо `-m repair_service` можно использовать `run_app.py`.

## Демонстрационные учётные записи

Только для отдельной демонстрационной базы с вымышленными данными:

| Логин | Пароль | Роль |
| --- | --- | --- |
| `admin` | `DemoAdmin!2026` | Администратор |
| `master` | `DemoMaster!2026` | Мастер Алексей Орлов |
| `master2` | `DemoMaster!2026` | Мастер Ирина Волкова |

Демо заполняется только при первом запуске пустой базы. Повторный запуск
не перезаписывает изменения.

Для пустой рабочей базы запускайте **без `--demo`**:

```bash
.venv/bin/python -m repair_service
```

Появится окно создания первого администратора. Затем добавьте мастера
в «Сотрудники», клиента в «Клиенты», устройство в «Устройства» и создайте заявку.
У рабочей базы нет встроенного пароля по умолчанию.

## Возможности

- Учёт клиентов и устройств, редактирование и безопасное удаление несвязанных записей.
- Заявки, неисправность, результаты диагностики, назначение мастера, плановая дата.
- Переходы между статусами и история с датой, сотрудником и комментарием.
- Услуги, количество и цена работ; точный расчёт в целых копейках.
- Цена добавленной работы не меняется при обновлении цены в справочнике.
- Поиск, в том числе по русским именам без учёта регистра, фильтры по мастеру и статусу.
- Сводка за период по дате приёма заявок.
- Доступ мастера только к назначенным заявкам. Администратор управляет справочниками.
- Изменение собственного пароля и отключение сотрудников.

Нельзя отключить мастера с незавершёнными заявками: сначала переназначьте их.
Выданные и отменённые заявки доступны только для чтения.
Удаление клиента или устройства, которое связано с другими записями, запрещено.
Для услуг вместо удаления используйте снятие флага доступности.

### Клавиатура

- `Ctrl+N` — новая заявка для администратора.
- `Ctrl+F` — поиск в журнале.
- `F5` — обновление.
- Стрелки — выбор строки, `Enter` — открытие заявки.
- `Tab` — переход по полям, `Esc` — закрытие формы.

## Данные и ограничения

Базы создаются в `repair_service/data/`:

- `demo.sqlite3` — демонстрация;
- `workshop.sqlite3` — рабочие данные.

Другую базу можно выбрать аргументом `--database /путь/к/файлу.sqlite3`.
Ошибки приложения записываются в `application.log` рядом с выбранной базой.
Старые папки `code/`, `codeMain/` и их базы приложение не использует.

Программа рассчитана на локальную учебную эксплуатацию. Пароли хешируются
PBKDF2-HMAC-SHA256 с солью и 600 000 итерациями. Сеансы хранятся только в памяти.
Однако **файл SQLite не зашифрован**: права внутри программы не защищают от
человека с прямым доступом к файлу. Не помещайте сюда реальные персональные
данные без отдельной оценки требований безопасности.

Сводка не заменяет бухгалтерский учёт: стоимость услуг не означает фактическую оплату.
Нет сетевого сервера, склада запчастей, печати актов, автоматического резервного
копирования или восстановления забытого пароля. Для резервной копии закройте
приложение и скопируйте нужный файл SQLite.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Тесты создают временные базы и не меняют рабочую или демонстрационную базу.
GUI-проверки используют Qt offscreen и не требуют окна на рабочем столе.
Только логика без установленного PyQt5:

```bash
python3 -m unittest discover -s tests -p test_workshop.py -v
```

Снять реальные окна приложения для курсовой:

```bash
.venv/bin/python tools/capture_ui.py
```

Снимки сохраняются в `docs/screenshots/`. Скрипт снимает только собственные
виджеты на временной базе, не рабочий стол.

| `demo.py` | Вымышленные примеры |
| `ui/common.py` | Общие формы и таблицы |
| `ui/dialogs.py` | Вход, первоначальная настройка и карточки |
| `ui/window.py` | Главное окно, журнал, справочники и сводка |
| `ui/theme.py` | Оформление Qt |
